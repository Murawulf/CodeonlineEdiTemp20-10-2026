Pourquoi crypto natif, pas jsonwebtoken ?

  • Surface minimale — HS256 trivial, inutile d'embarquer une lib tierce.
  • Contrôle du format — payload figé {sub,role,instance,iat,exp}, TTL 900 s.
  • Compatibilité — JWT HS256 standard, accepté par le verifyJWT des nœuds.
  • Moins de dépendances — risque supply-chain réduit, empreinte mémoire faible.

Modèle de données · détail

Le registre & le journal

partners — LE REGISTRE

Annuaire de référence par pays. Source unique de resolveRoute() (match exact GLN).

  • gln VARCHAR(13) UNIQUE — Global Location Number
  • name · country_code (ISO 3166 num.)
  • target_url webhook de réception EDI
  • status ACTIVE / INACTIVE — filtre de routage

transactions — JOURNAL (audit)

Une ligne par transmission. 115 lignes en prod.

  • status RECEIVED · FORWARDED · DELIVERED · FAILED · RETRY_QUEUED
  • transport_mode ORCHESTRATOR · P2P · P2P_SYNC
  • aperak_status PENDING / ACK / NACK
  • order_ref référence métier de commande (idx)

tracking_api_keys — SÉCURITÉ

Clés par application pour /api/tracking/*. 1 ligne en prod. Fallback : clé maître TRACKING_API_KEY.

  • scope full / readonly
  • status ACTIVE / REVOKED · expires_at NULL = jamais

order_tracking_summary — VUE

Agrégation par order_ref du cycle de vie. 19 lignes en prod.

  • has_orders … has_aperak — présence de chaque étape
  • lifecycle_status ORDERED → … → COMPLETED
  • has_errors · failed_steps

Logique de routage GLN

3 temps : exact → préfixe → null

routingService.resolveRoute(gln) — le registre fait foi, le préfixe est un filet de sécurité.

1 · Match EXACT

partners WHERE status='ACTIVE' → target_url. Source DATABASE. Cas nominal : le registre fait foi.

2 · Fallback par PRÉFIXE

SN… → Sénégal (686) · 619… → Tunisie (788) · 618… → Côte d'Ivoire (384). Source PREFIX_RULE.

3 · Sinon null

Destinataire inconnu → relais répond 404 et marque la transaction FAILED.

// 1. Match exact (le registre fait foi) const [rows] = await db.execute( 'SELECT target_url, country_code, name' + ' FROM partners WHERE gln = ?' + ' AND status = "ACTIVE"', [gln]); if (rows.length > 0) return { url: rows[0].target_url, source: 'DATABASE' }; // 2. Fallback par préfixe if (gln.startsWith('SN')) return senegal; if (gln.startsWith('619')) return tunisia; if (gln.startsWith('618')) return coteIvoire; // 3. Inconnu return null;
Smart routing — payload chiffré détecté (header/envelope P2P) → livraison détournée vers /api/p2p/receive.

Sécurité

Mécanismes en place & durcissement

En place

  • JWT de service HS256 — forgé par mintServiceToken(), exp +900s, signé JWT_SECRET.
  • Secret partagé réseau — JWT_SECRET identique par env, distinct DEV/PROD.
  • En-tête legacy x-api-pin transmis en parallèle.
  • Clé tracking double-vérif — clé maître ou clé ACTIVE en base, cache 60 s (401/403).
  • sanitizeError() — masque aes/rsa/PEM/base64 → [CRYPTO]. formatTx() n'expose jamais l'EANCOM.
  • Secrets externalisés — uniquement .env (git-ignored), jamais hardcodés.

Génération EANCOM / APERAK

Le hub est seul à générer les APERAK

Les nœuds postent un ACK/NACK via POST /api/orchestrator/ack ; le hub fabrique l'APERAK EANCOM D.96A conforme GS1 (BGM 313=ACK · 314=NACK).

Flux handleAck

  • Validation stricte (refs, status ∈ ACK/NACK, error_code si NACK)
  • generateAperakEANCOM(...) produit le D.96A
  • resolveRoute localise le fournisseur
  • dispatchMessage Bearer JWT + x-api-pin
  • _logAckEvent MAJ tx + INSERT APERAK DELIVERED
